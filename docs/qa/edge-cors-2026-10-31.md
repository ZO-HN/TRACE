# D02 milestone: shared browser Edge CORS

Status: implemented locally; staging and deployment unverified. Owner: TRACE maintainers. Date: 2026-10-31, Asia/Singapore. Sources: current handler/SDK inspection, [diagnosis D02](diagnosis-2026-10-31.md#d02--p1--browser-edge-function-cors-does-not-allow-the-installed-sdks-request-headers), [coaching specification](../features/coaching.md), and executed regressions.

## Scope and baseline

Outcome: remove the SDK preflight mismatch from `r2-presign`, `r2-get-url`, and `trace-brain` as a small phase-0 prerequisite to the [target architecture](../planning/architecture-evolution.md). This is within the first [priority group](../planning/open-items.md). Caching, AI redesign, media entitlement/schema/finalization and client UI changes are outside this milestone.

Web HEAD: `06675347e6b13085750cf319c3b66ffde4a6954e`; working branch `codex/edge-cors-contract`. Companion HEAD: `774ab9df80d423d76f4d5d5c134ba731d10339a9`, branch `codex/trace-reliability`. Both already had substantial uncommitted changes. Checks include those dirty sources; they are not evidence about HEAD alone. No existing edits were discarded and no mobile source was edited by this milestone. The earlier [preparation baseline](../development/phase-baseline-2026-10-31.md) remains a separate dated snapshot.

Fresh inspection confirmed all three handler allowlists still omitted `apikey` and `x-client-info`. Requests emitted by both installed Supabase SDKs include those headers with `authorization` and JSON `content-type`. The new regression suite failed all 24 cases before the fix and passed all 24 after it. This reestablishes the local D02 defect rather than assuming the dated diagnosis remains current.

## Acceptance and implementation

- OPTIONS permits every header emitted by either installed SDK, for local coach/mobile-web origin fixtures, without requiring authentication or constructing a service client.
- Successful POSTs and handled 400/401/403/405/500 responses retain consistent origin/method/header policy. Missing/invalid auth still denies requests; denied object/session access does not issue a signed URL.
- Upload/playback expiry and JSON shapes remain compatible. No SQL migration, generated type change, new credential, new dependency or client update is introduced.
- Real gateway, authenticated browser and R2-hop acceptance remain distinct release gates.

The three handlers import [shared policy](../../supabase/functions/_shared/cors.ts). It preserves the previous wildcard origin and POST/OPTIONS methods while adding only the missing SDK headers. [Regression tests](../../tests/edge/cors.test.ts) execute the actual TypeScript entry points after transpilation and load the actual shared module. Auth/DB/R2 services are fixtures; real SDK request construction and local handler branches execute. This does not prove RLS, foreign-key media entitlement, real object signing, live inference or Deno-native compilation.
