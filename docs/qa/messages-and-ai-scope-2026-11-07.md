## Human messages

Both apps now load the newest 50 conversation messages and expose **Load older messages**, using a stable `(created_at,id)` cursor. Tied timestamps and legacy null dates are paged deterministically; realtime overlap is deduplicated into the same chronological list. Loading, unavailable, empty and older-page failures are distinct; a failed page retains the messages already read. Account/peer/setup guards prevent stale callbacks or completed requests restoring another conversation. Conversation components are keyed by the two participants, so input from a previous conversation is not displayed or sent under a new peer.

`20261107030000_reliable_direct_messages.sql` adds the owner-scoped page RPC and `send_direct_message`. The captured sender must match authentication, and new messages require a current coach/trainee relationship. A stable client message UUID gives an exact content/participant receipt after a lost response. Changed content or ownership under that UUID is rejected. Confirming an already-sent owned message remains possible after the relationship ends; new sends then fail. Existing participant-history read policy and compatible legacy inserts remain intact. No real message was sent during these tests.

The hook keeps uncertain send IDs in its mounted conversation, coalesces repeated pending text and retains draft input after failures. Reopen/refresh persisted history before composing a different message after uncertainty; no automatic resend or cross-reload browser outbox was introduced. The server does not deduplicate distinct intentional messages by text. Read receipts, inbox events/provider notification delivery, and real hosted/realtime acceptance remain separate scopes.

Focused results: two database tests passed, including more than 200 messages with tied/null timestamps, exact send replay, changed content, forged sender/relationship denial and history isolation. Three actual-hook WEB lifecycle cases and five actual-React mobile hook cases passed. Generated types were regenerated through the existing generator; its initial inability to map a composite SETOF result was resolved by returning explicit typed table columns. No generated types were hand-edited.
